# DSM Terminal

DSM Terminal 是面向群晖 DSM 的轻量 Web SSH 工作台。目标设备是 DS218+（`apollolake` / x86_64），目标系统是 DSM 7.2.2。

当前为测试版本。2026-10-14 审查发现的三项认证与可用性问题已实施代码修复并增加回归测试, 但真实 DSM 安装、认证及双用户隔离仍待验收, 不能视为安全发布批准。部署边界见 [安全说明](docs/SECURITY_BOUNDARIES.md), 公开前需完成 [发布检查](docs/PUBLICATION.md)。

项目自身代码使用 [MIT](LICENSE); 第三方依赖保留其原始许可, 见 [第三方声明](THIRD_PARTY_NOTICES.md)。漏洞报告与安全不变量见 [SECURITY.md](SECURITY.md)。源码示例与私人定制包分离, 历史脱敏和日志边界见 [开源隐私说明](docs/OPEN_SOURCE_PRIVACY.md)。

当前里程碑已经具备可运行的 SSH 核心：

- React + TypeScript + xterm.js 终端界面
- Node.js + ssh2 后端，优先使用 WebSocket 传输终端数据，并在 WebSocket 不可用时自动回退到 HTTPS 事件轮询
- 完整 SSH PTY，支持 ANSI、256 色、TrueColor、UTF-8、中文和交互程序
- 密码及私钥认证
- 账号 + 密码, 账号 + 私钥, 账号 + 私钥 + 密码三种连接方式
- 按 DSM 用户隔离并加密保存 SSH 账号、密码、私钥和私钥口令, 支持临时连接和清除保存的凭据
- 六套深浅主题和自定义颜色, 界面与终端同步, 校验文字对比度
- 终端旁的 SFTP 文件管理, 支持详情列表、缩略图、图片/文本预览、目录导航、隐藏文件及排序
- 流式上传和下载, 拖放/多文件上传、进度与取消、覆盖确认、新建空目录、重命名、删除和权限修改
- 首次连接确认 SHA256 主机指纹；已知主机指纹变化时拒绝连接
- 多服务器配置、多终端标签和终端尺寸同步
- 一次性且区分用途的连接票据, 保存的凭据只在后端解密, 不回传密码和私钥
- 配置文件采用 `0600` 权限和原子写入

## 本地开发

需要 Node.js 22.22.3 或更高的受维护版本及 pnpm。SPK 使用官方 Node.js v22 套件。

```bash
pnpm install
pnpm dev
```

前端地址：<http://127.0.0.1:4173>

后端地址：<http://127.0.0.1:4174>

默认只监听回环地址，避免尚未接入 DSM 身份认证时暴露到局域网。

## 本地 SSH 集成测试

项目包含一个只监听 `127.0.0.1:22222` 的测试 SSH 服务：

```bash
pnpm --filter @dsm-terminal/server mock:ssh
```

测试账号为 `demo`，密码为 `dsm-terminal-demo`。每次启动都会生成新的临时主机密钥，用于验证首次指纹确认和指纹变化拦截流程。

## 构建群晖 SPK

```bash
pnpm package:spk
```

产物位于 `release/DSM-Terminal-0.2.3-0015-apollolake.spk`。套件依赖群晖官方 Node.js v22 (`22.22.3-1010` 或更高), 后端只监听 `127.0.0.1:46880`, 通过 DSM 官方第三方应用路径 `/3rdparty/DSMTerminal/` 访问。仅精确的应用会话交换路径向后端转交 DSM Cookie 和 SynoToken, 其余套件代理路径清除它们。后端执行固定路径的 DSM 官方认证助手, 仅使用助手验证得到的用户名和系统 UID 建立应用身份, 不再接受外部认证完成回调。真实 NAS 上套件用户执行该助手的权限与环境仍待验收。

`0014` 增加外部访问地址配置, 公开源码使用示例 `https://nas.example.com`, 部署前需替换或从本地配置构建, 修复 HTTPS 外层代理转至 DSM HTTP 5000 后浏览器模块被误拒绝的问题。配置保存在套件数据目录 `access.json`, 升级不覆盖。仍严格拒绝其他 Origin, 不信任任意转发头来放宽检查; 参见 [外部访问配置](docs/EXTERNAL_ACCESS.md)。

终端优先使用 WebSocket; 如果握手超时、协议异常或连接意外断开, 客户端重新签发一次性票据并自动切换到每次都会完整结束的 HTTPS 事件轮询。业务认证和指纹错误不会被当作网络故障回退。

打包使用独立的 hoisted 生产依赖目录, 不运行宿主平台的原生模块构建脚本, 不包含可选原生加速模块。生成正式 SPK 前会自动解包到临时目录, 验证服务能独立启动, 健康检查和 DSM 鉴权生效, 并检查脚本行尾与 Web 资源路径。`0011` 修复了 `0010` 解引用 pnpm 依赖链接后导致 `body-parser` 等间接依赖无法加载的问题。

## 安全边界

开发服务只允许回环监听和回环 Host, 使用独立的本地开发身份。生产环境必须明确配置认证模式; DSM 套件通过官方认证助手确认登录身份, 后端仍保持回环监听。新增服务器配置、保存的凭据和文件会话按 DSM 用户隔离。回环地址不是可信调用方证明。

### 凭据加密与备份

套件数据目录的 `credentials.key` 保存首次启动时生成的随机 256 位主密钥, 权限为 `0600`。通过 HKDF-SHA256 和经过 DSM 验证的用户身份派生各用户的密钥, 使用 AES-256-GCM 加密 SSH 账号、密码、私钥和口令, 并将用户和配置 ID 绑定到认证数据。用户名、UID 和 SynoToken 不是独立的秘密加密密钥。DSM 官方认证接口提供用户名, 没有在本项目使用的公开认证流程中提供适合长期解密的用户秘密。[群晖应用认证文档](https://help.synology.com/developer-guide/integrate_dsm/web_authentication.html)

备份时必须同时保留套件数据目录的 `profiles.json` 和 `credentials.key`。升级保留它们, 不得重建主密钥。丢失主密钥后无法恢复保存的账号及凭据。此方案保护磁盘中的明文凭据并隔离应用用户, 不承诺阻止能同时读取主密钥和密文的 NAS 管理员或 root。

旧版无用户归属的配置继续可见, 编辑时复制为当前用户的私有配置。旧记录不会被覆盖或删除。新配置的 SSH 用户名也加密保存; 名称、主机、端口和认证方式是配置元数据。界面只回显当前用户有权读取的用户名和是否保存凭据, 不回显密码或私钥。修改主机、端口、用户名或认证方式后清除旧凭据, 需要重新保存。

### 文件能力范围

文件管理连接远程 SSH 服务器的 SFTP 子系统, 不是绕过 SSH 权限访问 NAS 文件。列表提供名称、大小、修改时间、八进制权限, 详情增加 UID/GID。支持空目录删除和普通文件删除, 不递归删除目录。

单文件上传上限 1 GiB, 上传和下载走流式通道, 同名上传必须确认覆盖。上传中断时清理临时文件; 不支持断点续传。下载通过短期、单次使用的下载票据交给浏览器, 不在前端缓存整个文件。

预览支持 PNG/JPEG/GIF/WebP (最高 8 MiB) 和前 256 KiB 的 UTF-8 文本。图片验证文件头, SVG/HTML 不作为可执行页面展示; 二进制和大图片提示下载。缩略图仅自动读取不超过 512 KiB 的可见图片, 更大的图片可在选中后预览。每个用户最多 8 个文件会话, 无传输活动且 30 分钟未使用时关闭。

主题保存在当前浏览器, 不保存账号密码到浏览器持久存储。手机上文件视图占满工作区, 可通过“文件”按钮切回终端。

修改服务器主机名或端口会自动清除旧指纹，下一次连接必须重新确认。用户名或认证方式变化不会清除主机指纹。
