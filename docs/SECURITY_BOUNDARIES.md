# 安全边界与部署说明

## 当前状态

2026-10-14 对当前工作区进行了审查, 发现一项高风险认证问题和两项中风险可用性问题。三项已实施代码修复并增加正向/反向回归; 真实 DSM 的认证助手权限、安装升级和双用户隔离仍待验收。不能据此承诺“没有风险”或安全正式发布。

完整扫描报告及后续修复证据保存在本地 Codex Security 结果中, 不在公开仓库里存放真实凭据和请求令牌。原扫描作为修复前快照保留, 不用修复结果覆盖历史结论。

## 认证与身份

SPK 以 `DSMTerminal` 套件用户运行, 监听 `127.0.0.1:46880`, 开启 `DSM_TERMINAL_AUTH_MODE=dsm-cgi`, 由 DSM Nginx 提供应用访问路径。

正常认证流程为浏览器申请 challenge, 向精确的 `/api/auth/session` 路径发送 DSM Cookie 与 SynoToken。后端只执行固定官方路径的 `authenticate.cgi`, 使用白名单 CGI 环境、超时和输出上限; 从其输出取得用户名, 再通过固定 `id` 程序查询 UID, 不接受请求声明的用户名或 UID。challenge 在验证前即消费, 失败不能重放, 同时运行的认证助手最多 8 个。应用 bearer token 用于后续 API; SSH 和 SFTP 使用短期、一次性、区分用途的票据。

已删除外部 `auth.cgi` 桥和后端认证完成回调。后端直接拒绝内部接口空间, 启用路径大小写与尾斜杠严格匹配; 即使绕过 Nginx, 本机进程也不能仅凭回环来源安装指定身份。认证助手缺失、超时或权限不足时拒绝认证, 不回退到开发身份。官方文档要求传入 Cookie 与客户端/服务器地址等 CGI 环境, 但本套件用户能否在目标 NAS 执行该助手仍需实测。[DSM 官方认证说明](https://help.synology.com/developer-guide/integrate_dsm/web_authentication.html)

`allUsers: false` 只是在套件入口配置中声明可见性, 不能据此承诺所有后端请求都限于 `administrators`。当前后端和 CGI 没有明确的管理员组校验。实际 DSM 外层访问控制必须独立验证。

普通开发模式使用本地开发身份, 不是生产鉴权。开发模式拒绝非回环监听与非回环 Host; 生产环境未明确配置合法认证模式会拒绝启动。不得通过其他反向代理向非可信网络暴露开发服务。回环监听不是对其他本机进程的身份验证。

外部来源由管理员的 `access.json` 明确配置, 本次套件预设 `https://nas.example.com`。配置存在时严格比对 Origin, 解决双层反代最后一跳 HTTP 的误判, 不通过接受任意转发头或关闭检查来放行。非法配置拒绝启动, 升级保留已有文件。详见 [外部访问配置](EXTERNAL_ACCESS.md)。

## 凭据保护

SSH 账号、密码、私钥和私钥口令在后端保存前使用 AES-256-GCM 加密。每用户密钥由随机 256 位主密钥与用户身份通过 HKDF-SHA256 派生, 认证数据绑定用户及配置 ID。UID、用户名和 SynoToken 不是秘密主密钥。

主密钥文件 `credentials.key` 与 `profiles.json` 位于配置的数据目录, 新文件使用受限权限。备份和恢复必须同时保留二者, 丢失主密钥无法恢复保存凭据。不要提交或发布它们, 即使配置文件是密文。

该机制不保护能同时读取主密钥和密文的 NAS root/管理员, 也不能弥补认证主体被伪造的问题。名称、主机、端口和认证方式仍是配置元数据。旧版无归属配置继续共享可见, 编辑时复制为当前用户的私有配置。

前端不把密码/私钥写入 localStorage。临时输入的凭据会在打开的 React 会话内存中保留以支持重连; 关闭会话移除引用不保证内存立即清零。不要将它描述为浏览器端加密保存。

## SSH 与文件操作

初次连接需要确认 SHA256 主机指纹, 已保存指纹变化时拒绝连接。确认前应通过可信渠道核对指纹, 不能仅凭弹窗确认服务器真实性。

生产文件操作使用目标 SSH 服务器的 SFTP 子系统和该 SSH 账号的权限, 不使用套件用户的本地文件权限。远程路径可覆盖该账号有权访问的范围, 并非限制在 home 目录内的沙箱。

上传走流式通道, 单文件上限 1 GiB, 使用临时文件及显式覆盖确认。仅支持文件和空目录删除, 不递归删除目录。文本预览限制前 256 KiB; 栅格图片预览验证文件头并限制 8 MiB, HTML/SVG 不作为可执行页面展示。下载使用 30 秒、单次使用的随机能力令牌。

能力令牌即使短期有效也属于敏感信息。日志、截图和反向代理访问日志中应避免保留带 ticket/token 的完整 URL。仅精确会话交换路径向 Node 转交 DSM Cookie 和 SynoToken; 其他套件代理路径显式清除两者。不得记录 Cookie、Authorization 或完整认证查询参数; 外层 DSM/自定义反向代理日志也需要单独检查。

## 可用性与已知缺口

WebSocket 在升级前消费有效终端票据并取得配额, 无效票据不返回 101。连接最先注册协议 `error` 处理, 错误仅终止当前连接; 限制帧大小、消息结构与待发送缓冲, 心跳负责回收失联连接。

WebSocket 与 HTTP 终端共享每用户 8 个、全局 64 个挂起/活跃连接配额。HTTP 首次附加超时 30 秒, 后续客户端租约 30 秒, 长轮询最多 10 秒; SSH 输出不会替弃用客户端续租。轮询中断、响应错误、慢客户端、关闭和超时均回收连接。已关闭会话仅短期保留事件, 数量同样有界。

终端与 SFTP 都持有并在关闭时销毁底层 TCP socket, 不依赖对端配合完成 SSH/TCP 半关闭。SFTP 挂起/活跃连接每用户最多 8 个、全局最多 64 个; 保留建立超时和 30 分钟空闲回收。这些上限不等于抵御所有洪泛或保证任意 NAS 的性能, 外层代理仍需按设备资源限制并发和请求速率。

SPK 依赖官方 Node.js v22 `22.22.3-1010` 或更高, 不再查找 PATH 中的任意 Node。Node.js 20 已结束上游安全维护, 不应用其运行安全版套件。[Node.js 维护状态](https://nodejs.org/en/about/eol)

## 验证边界

本次静态审查覆盖当前源码、配置、文档、测试夹具和锁文件。未发现真实生产凭据嵌入当前公开候选文件; demo 密码仅用于明确的回环 mock, 测试私钥运行时生成。

额外检查了本地可达的两个 Git 提交中的常见秘密模式与命中上下文, 没有发现真实密钥或密码; 未审计不可达对象、其他克隆和远端不可见引用。`pnpm audit --json` 当次返回已知漏洞 0, 不证明供应链或将来的依赖无风险。

类型检查、回归和解包启动用于验证当前修改, 不替代真实 DSM Nginx、CGI、升级和权限测试。忽略目录中的旧包、用户日志、截图和运行数据不因源码审查通过而自动获准公开。真实 NAS 验收必须包括两个 DSM 用户和认证失败场景, 不能只测试管理员成功登录。

公开与发布前的验收项见 [PUBLICATION.md](PUBLICATION.md)。
