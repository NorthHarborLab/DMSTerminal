# 部署与凭据保护

## 部署结构

DSM Terminal 的后端以 `DSMTerminal` 套件用户运行，监听 `127.0.0.1:46880`，由 DSM Nginx 通过 `/3rdparty/DSMTerminal/` 提供访问。浏览器通过 DSM 登录建立应用身份，再使用应用会话访问 SSH 和 SFTP 功能。

部署时应保留后端回环监听，在面向浏览器的入口使用 HTTPS，并通过 DSM 与外层代理配置访问范围。套件入口的 `allUsers: false` 不等于后端 `administrators` 组校验；后端不以管理员组成员身份作为统一访问条件。

开发模式使用独立的本地开发身份，只允许回环监听和回环 Host。不要通过反向代理将开发服务暴露到非可信网络。生产环境必须明确配置合法认证模式，回环来源本身不代表可信身份。

## DSM 身份认证

套件使用 `DSM_TERMINAL_AUTH_MODE=dsm-cgi`。浏览器先申请 challenge，再通过精确的 `/api/auth/session` 路径提交 DSM Cookie 和 SynoToken。后端执行固定路径的官方 `authenticate.cgi`，从验证结果取得用户名，再通过固定的 `id` 程序查询 UID。

- 不采纳请求自报的用户名、UID 或代理身份头。
- challenge 在验证开始前消费，认证失败后不能重放。
- 官方助手使用白名单 CGI 环境、执行超时和输出上限，同时运行的助手最多 8 个。
- 助手缺失、超时、输出无效或权限不足时拒绝认证，不切换到开发身份。
- 应用 bearer token 用于后续 API；SSH 和 SFTP 另用短期、一次性、区分用途的票据。

仅会话交换路径向后端转交 DSM Cookie 和 SynoToken，其他套件代理路径清除这两项。认证失败时应检查套件进程身份、官方助手路径与执行权限，以及代理转交的必要请求信息。[DSM 官方认证说明](https://help.synology.com/developer-guide/integrate_dsm/web_authentication.html)

## 外部访问地址

管理员通过套件数据目录的 `access.json` 指定允许的 HTTPS Origin。源码和通用包使用示例 `https://nas.example.com`，部署时应设置自己的地址。

配置生效后，浏览器请求的 Origin 必须与之严格一致，不依赖任意转发头放宽检查。非法配置会阻止启动，升级保留已有配置。外层 HTTPS 转发到 DSM HTTP 端口时仍使用同一允许来源；这项配置不负责加密代理之间的内部链路。

配置格式、端口与反向代理要求见 [外部访问地址配置](EXTERNAL_ACCESS.md)。

## 凭据存储与备份

SSH 账号、密码、私钥和私钥口令在后端保存前使用 AES-256-GCM 加密。每用户密钥由随机 256 位主密钥与用户身份通过 HKDF-SHA256 派生，认证数据绑定用户与配置 ID。用户名、UID 和 SynoToken 不作为秘密主密钥。

套件数据目录包含：

| 文件 | 用途 |
| --- | --- |
| `profiles.json` | 服务器元数据、加密后的账号和保存凭据 |
| `credentials.key` | 首次启动生成的主密钥 |
| `access.json` | 管理员配置的外部 HTTPS 来源 |
| `dsm-terminal.log` | 应用运行日志 |

主密钥与配置文件使用受限文件权限。备份与恢复必须同时保留 `profiles.json` 和 `credentials.key`，并限制备份读取权限。不要删除主密钥来排查连接错误；丢失它后无法恢复保存的凭据。

加密保护保存凭据不以明文落盘，并结合应用身份实施用户隔离。能同时读取主密钥与密文的 NAS root 或管理员仍可取得其中内容。服务器名称、主机、端口和认证方式属于明文配置元数据。

旧版未记录用户归属的配置继续共享可见，编辑时会复制为当前用户的私有配置。新的账号和保存凭据按用户管理，API 不回传保存的密码或私钥。

前端不将密码或私钥写入 localStorage。为支持重连，临时输入的凭据可保留在打开的页面会话内存中；关闭会话移除引用不代表立即清零浏览器内存。

## SSH 身份与文件权限

首次连接时应通过可信渠道核对 SHA256 主机指纹，不能仅凭弹窗判断服务器真实性。已保存指纹发生变化时拒绝连接；修改主机或端口后需要重新确认。

文件操作通过远程服务器的 SFTP 子系统执行，使用该 SSH 账号的权限。可访问范围不限定于 home，也不是套件用户的 NAS 本地文件沙箱。

| 能力 | 范围 |
| --- | --- |
| 上传 | 流式传输，单文件最多 1 GiB，使用临时文件和显式覆盖确认 |
| 删除 | 普通文件与空目录，不递归删除非空目录 |
| 文本预览 | UTF-8 文本的前 256 KiB |
| 图片预览 | PNG、JPEG、GIF、WebP，验证文件头，最多 8 MiB |
| HTML / SVG | 不作为可执行预览页面展示 |
| 下载 | 30 秒有效、单次使用的随机下载票据 |

## 连接与资源限制

WebSocket 在升级前验证并消费终端票据、取得连接配额。协议错误仅关闭当前连接，消息结构、帧大小和待发送缓冲均有限制，心跳用于回收失联连接。

WebSocket 与 HTTP 终端共享每用户 8 个、全局 64 个连接配额。HTTP 首次附加超时和客户端租约均为 30 秒，单次长轮询最多 10 秒；远程 SSH 输出不会替代客户端续租。

SFTP 每用户最多 8 个、全局最多 64 个连接，保留建立超时和 30 分钟空闲回收。终端与 SFTP 关闭时销毁底层 TCP socket，不依赖远端配合完成半关闭。外层代理仍应根据设备资源设置适当的并发和请求速率。

## 日志与问题反馈

应用日志可能记录服务器地址、端口和配置 ID。下载票据与终端票据即使短期有效，也应作为敏感信息处理。

- 不公开运行数据、主密钥、私人配置或包含真实连接信息的日志。
- 不记录 Cookie、Authorization、SynoToken 或带完整 ticket/token 的 URL。
- 外层 DSM 和自定义反向代理的访问日志需要单独配置脱敏策略。
- 分享日志或截图前移除服务器信息、个人目录、账号和认证材料。

安装及排障命令见 [安装指南](../release/README.md)，漏洞报告方式见 [SECURITY.md](../SECURITY.md)。
